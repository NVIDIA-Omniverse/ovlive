# LiveService wire schema

`nvidia/omniverse/live/v1alpha/live.proto` is a copy of the live edit service's `nvidia/omniverse/live/v1alpha/live_service.proto` and carries the additions the next paragraphs describe. The service owns the LiveService schema; this copy carries the write operation IDs. The copy keeps the `live.proto` name, from which protoc names the `live.grpc.pb.h` header the runtime includes and the `live_pb2.py` module the reference service imports; the file name is not part of the wire contract.

The copy adds the agreed client keepalive fields to the upstream bytes, ahead of the live edit service's own change: `JoinSessionHeader.client_keepalive` (field 3), `SessionConnected.keepalive_interval_ms` (field 2) and the empty `JoinSessionKeepalive` message as `JoinSessionRequest.keepalive` (field 3), with comments on the `JoinSession` keepalive rule and its `CLIENT_KEEPALIVE_TIMEOUT` reason. The service team checked their names, field numbers and error reason against the service's own keepalive change, which is not yet merged; they are reconciled with the service's schema when the service and its proto move into this repository.

The copy adds the chained-writes extension agreed with the live edit service team, ahead of the service's own change: the `ChainedUpdateLayerHeader` message with its `no_wait` flag (field 3), the `UpdateLayerRequest.chained_header` arm (field 3), the `PingResponse.operation_ids` (field 3) and `PingResponse.chained_writes` (field 4) capability flags, and, in the message's comment, the agreed semantics: a chained call waits for its predecessor unless `no_wait`, a cancelled waiting call applies nothing while a call the service handed to its store may still be written later, right after its predecessor, the `PREDECESSOR_NOT_COMMITTED` refusal carries `last_record` and `last_operation_id` metadata, and every `INVALID_ARGUMENT` a chaining replica gives a chained call carries an `ErrorInfo` (`INVALID_UPDATE`). Its shape, field numbers included, is reconciled with the service's when the service and its proto move into this repository.

The copy adds the merge-owner lease fields from the design, section 5.1, ahead of the live edit service's own change: `JoinSessionHeader.merge_owner` (field 4), `JoinSessionRequest.merge_owner` (field 4, the `MergeOwnerRequest` message), `SessionConnected.merge_owner` (field 3), `JoinSessionResponse.merge_owner` (field 5, the `MergeOwnerState` message), the `MergeOwnerAction` and `MergeOwnerOutcome` enums, `PingResponse.merge_owner` (field 5) and `Session.merge_owner_user_name` and `merge_owner_epoch` (fields 5 and 6), with comments on the `JoinSession` merge-owner rule. Every addition is a placeholder; its names and field numbers are reconciled with the service's schema when the service implements the lease.

The upstream file carries its own NVIDIA copyright and Apache-2.0 SPDX header, retained with the rest of its bytes. Its `go_package` and `java_*` options do not affect the C++ and Python code generated here. Generated sources are build outputs, not checked-in copies. Only this service is generated; no storage/notification/Nucleus service is used.
